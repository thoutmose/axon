# 0030 — The library is one roadmap, with its plan

- **Status:** Accepted
- **Date:** 2026-10-13
- **Epic:** EP-95
- **Supersedes:** the library of ADR 0014 and the OSSU import of ADR 0013

## Context

The owner follows one roadmap, *Top-5% in 26 engineering domains*, written in their vault with its goal, milestones, projects, habits, and first tasks. They asked for it to be Axon's only roadmap, used by default and in the demo, with everything related to it. The curated library (27 domains) and the OSSU curriculum each started skills only; the plan around them had to be built by hand.

## Decision

- The library holds that one roadmap. Its 26 domains are hard skills in seven areas, each with its proof and resources; six soft skills the plan relies on are listed too. OSSU and the other domains are removed, along with the regrouping of old imports that depended on them. Roadmaps people already imported are their data and stay.
- A library roadmap can carry a **plan**. Starting it creates, in one transaction, the goal, a milestone and a project per phase (the exit check on the board as an epic, issues, and subtasks), the side projects, the habits, the first tasks, the areas, the resources, and the roadmap's note, all connected. It starts once.
- The plan keeps its own dates while its first phase runs, so it matches the vault; started later, it starts on the coming Monday. Placement by the skills assessment marks domains as being learnt, never done: each needs its external proof.
- It is offered, not imposed: a new account starts it with one button, so a household member is not handed a 3,700-hour plan.

## Consequences

Starting the roadmap gives a working plan in seconds, and the demo shows Axon used for a real, long project. The library no longer offers other domains; the Tutor agent drafts any other roadmap on request (ADR 0014), and roadmaps can still be built by hand.
