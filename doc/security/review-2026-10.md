# Security review before 1.0 (2026-10-11)

EP-21 asks for an **external** security review with no open high-severity issue. This document is the maintainer's internal review that prepares it: what was checked, what was found, and what was fixed. The external review is still to be done by someone independent; its findings will be added here.

## Scope

The API (`api/`), the web app (`web/`), the Compose stack and Caddy configuration, the Anki bridge, the backup image, and CI. Out of scope: the hosts themselves (fleet repository, ADR 0004).

## Automated checks

| Check | Where | Result |
|---|---|---|
| Reachable Go vulnerabilities (govulncheck, with the release toolchain Go 1.26.9) | now in CI | 0. One advisory in `golang.org/x/crypto` has no fix and is not reachable. |
| npm advisories, production dependencies | `npm audit --omit=dev` | 0 |
| Fixable HIGH and CRITICAL image vulnerabilities (Trivy 0.74) | CI, every image | 0 in api, web, backup, anki, caddy, db (see the 2026-10-14 update) |

| Static analysis (golangci-lint with gosec, errorlint, staticcheck) | CI | clean; every `nolint` carries its reason |
| Authorisation matrix | integration tests | every user-owned endpoint answers 404 to another person (one test per area) |
| OpenAPI contract and coverage | integration tests | every operation is exercised and its responses validate |

## Manual review

| Area | Finding | Status |
|---|---|---|
| Authentication | Passkeys only, per-IP limits on every sign-in endpoint, TOTP each code once. Recovery sign-in with an authenticator: a stolen recovery code allowed unlimited guesses at the 6-digit code across IP addresses. | **Fixed (medium):** five wrong codes lock recovery for the account for 15 minutes; failures are audited (`signin.recovery_failed`). |
| Sessions | 256-bit tokens, hashed; `HttpOnly`, `Secure`, `SameSite=Lax`; new session on every sign-in. | OK |
| CSRF | State-changing requests require a same-origin `Origin` header; tokens use `Authorization`. | OK |
| XSS | Svelte escapes output; the three `{@html}` uses render escaped Markdown and search snippets (`escape` before marking); CSP `default-src 'self'`, no inline scripts, `frame-ancestors 'none'`. | OK |
| Headers | HSTS, `nosniff`, `Referrer-Policy: no-referrer`, no `Server`. Changes to the Caddyfile never reached the servers: `rsync` replaced the bind-mounted file, and Caddy kept the old one. | **Hardened:** added `Permissions-Policy` (camera, microphone, geolocation, payment, USB off); **fixed:** `deploy.sh` recreates Caddy on every deploy. |
| SSRF | Page fetches for agents (`internal/web`) are allowlisted, refuse private and loopback addresses, and respect robots.txt; catalogue clients (TMDB, Open Library, Open Food Facts, USDA) only call fixed hosts, with HTTPS-only or no redirects; the Anki bridge address comes from the operator. | OK |
| Injection | SQL through pgx parameters; identifiers in the instance archive go through `pgx.Identifier`; no shell execution. | OK |
| Uploads | 12 MB limit on upload routes, 64 KB elsewhere; images re-encoded (no metadata survives); covers type-checked from the bytes and at most 2 MB. | OK |
| Secrets at rest | TOTP secrets, AI keys, repository and Anki credentials sealed with AES-256-GCM (`AXON_ENCRYPTION_KEY`); never returned by the API. | OK |
| AI agents | Tools are allowlisted per skill; writes are proposals that need approval; injected instructions in data are tested; health data needs its own consent and health safety guards run without the model. | OK |
| Privacy | Consents default off; health data deleted on withdrawal; export and erasure complete. | OK |
| Denial of service | Bodies bounded, lists paginated, analytics bounded (one year in under 3 s), catalogue lookups rate-limited per person and paced per provider. | OK |

## Update, 2026-10-14

A CVE check of everything the stack runs, not only the images Axon builds:

- **Caddy** (`caddy:2-alpine`, the newest upstream image) was built with Go 1.26.8 and `golang.org/x/net` 0.59.0: four HIGH denial-of-service flaws (crafted HTTP Range headers, HTTP/2 SETTINGS floods, TLS ECH). The Range one was reachable. **Fixed:** `deploy/caddy` builds the same Caddy (v2.11.7, standard modules) with Go 1.26.9 and `x/net` 0.60.0 on the upstream image.
- **PostgreSQL** (`pgvector/pgvector:pg16`, the newest upstream image) carried 29 HIGH or CRITICAL Debian package flaws (perl, pcre2) and 25 in `gosu`, built with Go 1.24.6. The database is not published outside the compose network. **Fixed:** `deploy/db` applies Debian's security updates and rebuilds `gosu` 1.19 with Go 1.26.9; same PostgreSQL 16 and Debian release, so the data directory and collations are unchanged (checked on a live volume: same rows, pgvector working).
- Both images are now built, scanned, and shipped like Axon's own (CI matrix, `deploy.sh`), so the Trivy gate covers them. Caddy no longer needs `NET_BIND_SERVICE`: the rebuilt binary has no file capability and listens on 3000.
- Not reachable, left as is: `cookie` 0.6.0 bundled by SvelteKit 2 (low; Axon's web server writes no cookie; fixed by SvelteKit 3) and GO-2026-5932 in `golang.org/x/crypto/openpgp` (no fix; not used).
- Outside this repository: on `srv-dev`, cAdvisor (8080), the node exporter (9100), and promtail (9080) listen on every interface. Their binding belongs to the fleet repository (ADR 0004).

## Update, 2026-10-17

The check again, every image and dependency, before 1.0:

- **Go** (govulncheck 1.9.0): 0 reachable. **npm**: 0 in production dependencies; the three low `cookie` advisories above are unchanged (fixed only by SvelteKit 3).
- **Images** (Trivy 0.74, HIGH and CRITICAL, fixed or not): api, web, and caddy have none; anki (Debian 13) has 44 HIGH findings with no fix released, all in Debian packages (ncurses, systemd, util-linux, acl) and none in its Python libraries.
- **db**: `gnupg` and SQLite only served to add PostgreSQL's apt key when the upstream image was built. **Fixed:** `deploy/db` purges them, which removes one CRITICAL and three HIGH flaws (SQLite, ncursesw); checked on the live volume (same rows, pgvector 0.8.7). Two CRITICAL flaws remain, both with no Debian 12 fix and both unreachable: CVE-2023-45853 is in zlib's minizip, which Debian's `zlib1g` does not ship, and CVE-2026-6653 needs PostgreSQL to parse crafted XML, which Axon never sends it (no `xml` type or function in any query or migration), on a database that is not published outside the compose network. Moving to Debian 13 would clear them but changes glibc, so every text index would need a rebuild: that waits for the next PostgreSQL major upgrade, which rebuilds the data directory anyway.
